# «Печатает…» и другие действия: общие сценарии

Индикатор «кто чем занят» в личных чатах и группах реализуется в Orbitle дважды: на Swift
(`orbitle-ios`) и на Kotlin (`orbitle-shared`, Android и Desktop). Эти файлы — общие сценарии
для обеих реализаций, чтобы они не разошлись: какой текст показать, сколько живёт отметка и
когда отправлять свой кадр.

Swift проигрывает их в `TypingFixtureTests` (`orbitle-ios/Tests/OrbitlePresentationTests`).
Kotlin-проигрыватель пишется отдельно и должен гонять все файлы каталога, как и Swift: новый
файл без проигрывателя — ошибка теста.

## Протокол

- `MSG_TYPING` 65, клиент → сервер, ответа нет: `{"chatId": …, "type": "…"}`, в комментариях
  к посту канала ещё `"postId"`.
- Пуш `NOTIF_TYPING` 129: `{"chatId": …, "userId": …, "type": "…"}`.

Значения `type`:

| `type` | Действие | Один | Несколько |
|---|---|---|---|
| `TEXT` | набирает текст | печатает | печатают |
| `AUDIO` | записывает голосовое | записывает аудио | записывают аудио |
| `VIDEO_MSG` | записывает кружок | записывает видеосообщение | записывают видеосообщение |
| `PHOTO` | отправляет фото | отправляет фото | отправляют фото |
| `VIDEO` | отправляет видео | отправляет видео | отправляют видео |
| `FILE` | отправляет файл | отправляет файл | отправляют файл |
| `STICKER` | выбирает стикер | выбирает стикер | выбирают стикер |

Пустой, отсутствующий и незнакомый `type` в пуше — `TEXT`.

## Файл

У каждого файла есть `kind` — по нему проигрыватель выбирает правила: `texts`, `expiry` или
`sending`. `name` совпадает с именем файла, `description` — для человека. Время везде в
миллисекундах от начала сценария, id — строки.

### `texts` — какой текст показать

```json
{
  "kind": "texts",
  "name": "texts-group",
  "cases": [
    {
      "name": "two",
      "chat": "group",
      "typing": [
        {"userId": "1", "name": "Иван", "type": "TEXT", "startedAt": 0},
        {"userId": "2", "name": "Петя", "type": "TEXT", "startedAt": 1000}
      ],
      "list": "Иван и Петя печатают…",
      "header": "Иван и Петя печатают"
    }
  ]
}
```

- `chat` — `private`, `group` или `channel`.
- `typing` — печатающие в любом порядке. `name` — уже только имя (без фамилии), `null` —
  имя неизвестно. `type` — как пришёл в пуше: строка, `null` или поля нет. `startedAt` —
  когда пользователь начал (первый пуш после паузы). Проигрыватель сам сортирует по
  `startedAt`, при равенстве — по `userId`.
- `list` — текст строки списка чатов, `header` — второй строки шапки чата. `null` — индикатора нет.

Правила:

1. Канал и пустой список — `null`.
2. Личный чат — только действие того, кто начал раньше: «печатает…», без имени.
3. Группа: берётся `type` того, кто начал раньше всех; в строке только печатающие с тем же
   типом, по времени начала. Имена: один — «Иван», два — «Иван и Петя», три — «Иван, Петя и
   Маша», четыре и больше — «Иван и ещё 3». Дальше глагол: единственное число только для
   одного человека («Иван печатает…», «Иван и Петя печатают…»).
4. Нет нужного имени (до трёх нужны все, с четырёх — только первое): счёт, как раньше было в
   iOS (`ChatListFormatter.typingText`): «2 участника печатают…», «5 участников отправляют
   файл…», «21 участник печатает…» (после числа на 1, кроме 11, — единственное число).
   Один печатающий без имени — только действие: «выбирает стикер…».
5. Строка списка кончается «…». Шапка — тот же текст без «…» в конце: в iOS точки рисует
   экран (бегущие точки перед текстом), так было и до этих правил.

### `expiry` — сколько живёт отметка

```json
{
  "kind": "expiry",
  "name": "expiry-ttl",
  "ttlMs": 8000,
  "steps": [
    {"at": 0, "push": {"chatId": "c1", "userId": "1", "type": "TEXT"}},
    {"at": 3000, "message": {"chatId": "c1", "userId": "1"}},
    {"at": 8000, "expect": {"c1": [{"userId": "1", "type": "TEXT"}]}}
  ]
}
```

Шаги идут по порядку, `at` не убывает:

| Шаг | Что делает |
|---|---|
| `push` | пришёл пуш 129; `type` может быть строкой, `null` или отсутствовать |
| `message` | пришло сообщение от `userId` в `chatId` |
| `expect` | кто печатает на момент `at`: id чата → печатающие по времени начала |

Правила:

- Отметка живёт `ttlMs` (8 с) после последнего пуша этого пользователя в этом чате,
  включительно: пуш в 0 — в 8000 ещё печатает, в 8001 уже нет.
- Повторный пуш, пока отметка жива, продлевает срок и заменяет тип; место в очереди
  (`startedAt`) остаётся. Пуш после истечения — новое начало, пользователь встаёт в конец.
- Сообщение пользователя сразу снимает его отметку в этом чате (в других чатах она остаётся).
  Сообщение от того, кто не печатает, ничего не меняет.
- В `expect` перечислены все чаты, где кто-то печатает; чатов без печатающих в нём нет,
  `{}` — никто. `type` — как пришёл: пустая строка и отсутствие — `null`, незнакомое значение
  хранится как есть (показывается как `TEXT`, это проверяют `texts`).

8 с — срок веб-клиента Max. В iOS `ChatRepositoryImpl.typingTTL` (`TypingTracker.defaultTTL`)
теперь 8 с; ядро (`MaxState.DEFAULT_TYPING_TTL_MS`) пока держит 6 с, его владелец предупреждён.

### `sending` — когда отправлять свой кадр 65

```json
{
  "kind": "sending",
  "name": "sending-text",
  "steps": [
    {"at": 0, "do": "editText", "chatId": "c1", "sent": [{"chatId": "c1", "type": "TEXT"}]},
    {"at": 1000, "do": "editText", "chatId": "c1", "sent": []}
  ]
}
```

| `do` | Событие | Поля |
|---|---|---|
| `editText` | правка текста в поле ввода | `chatId` |
| `startRecording` | началась запись | `chatId`, `type`: `AUDIO` или `VIDEO_MSG` |
| `stopRecording` | запись кончилась (отправлена или отменена) | `chatId` |
| `uploadProgress` | ход загрузки | `chatId`, `type`: `PHOTO`, `VIDEO` или `FILE` |
| `openStickers` | открыта панель стикеров | `chatId` |
| `tick` | таймер повторов | — |

Необязательные поля: `postId` (комментарий к посту, уходит в кадре) и `canWrite` (по
умолчанию `true`; `false` — писать сюда нельзя, например канал без прав).

`sent` — ровно те кадры, что отправлены этим шагом, по порядку; `[]` — ничего. У кадра нет
поля `postId`, если его не было у события.

Правила:

- Порог один на чат, общий для всех типов: кадр не уходит, если в этот чат что-то отправлено
  меньше 6000 мс назад (ровно через 6000 — уходит). Пропущенный кадр время порога не сдвигает.
- `TEXT` — на каждую правку текста. `PHOTO`, `VIDEO`, `FILE` — на каждое событие хода загрузки.
  `STICKER` — при открытии панели, без повторов.
- `AUDIO` и `VIDEO_MSG` — в начале записи и затем каждые 5000 мс от её начала, пока запись идёт.
  Повтор тоже проходит порог, поэтому при непрерывной записи кадр уходит в 0, 10 с, 20 с.
  `tick` в момент `at` делает повторы всех записей, чьё время пришло (несколько пропущенных
  шагов дают один кадр, порядок — по `chatId`); `tick` до срока ничего не делает. Повторы
  считаются от начала записи, даже если первый кадр не ушёл из-за порога.
- Отдельного «перестал» нет: у получателя отметка истекает сама.
- `canWrite: false` — ничего не уходит, запись не запоминается (повторов нет) и порог не трогается.

## Swift

`TypingFixtureTests` читает файлы с диска, путь — от `#filePath` теста вверх до корня
репозитория: `test-fixtures/typing`, как `CallSessionFixtureTests` для звонков. Тексты
проверяются через `TypingFormatter`, строку `ChatListFormatter.item` и шапку
`ChatHeaderStatus.make`, сроки — через `TypingTracker`, отправка — через `TypingSendPolicy`.
