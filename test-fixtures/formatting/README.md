# Форматирование текста: общие сценарии

Разметка текста (`elements` сообщения) читается и пишется в Orbitle дважды: на Swift
(`orbitle-ios`) и на Kotlin (`orbitle-shared`). Эти файлы — общие сценарии для обеих
реализаций. Swift проигрывает их в `FormattingFixtureTests`
(`orbitle-ios/Tests/OrbitleDomainTests`), логика — `MessageMarkup` в `OrbitleDomain`.
Проигрыватель должен гонять все файлы каталога: новый файл без проигрывателя — ошибка теста.

## Протокол

Элемент сервера: `{type, from, length, attributes?, entityId?}`. Смещения — в **единицах
UTF-16** (как `String.length` в JS): эмодзи вне BMP — две единицы, флаг — четыре, кириллица —
одна на букву.

| Тип | Что это | Панель поля ввода |
|---|---|---|
| `STRONG` | жирный | да |
| `EMPHASIZED` | курсив | да |
| `UNDERLINE` | подчёркнутый | да |
| `STRIKETHROUGH` | зачёркнутый | да |
| `MONOSPACED` | моноширинный | да |
| `LINK` | ссылка, адрес в `attributes.url` | да (действие «Ссылка») |
| `QUOTE`, `HEADING` | цитата, заголовок | нет: читаются и при правке сохраняются как есть |
| `CODE` | читается как `MONOSPACED` | нет |
| `USER_MENTION`, `ANIMOJI` | упоминание, анимодзи | ставятся отдельно (не в этих сценариях) |

Спойлера в протоколе нет. Отправка: `MSG_SEND` 64 `message.elements`; правка: `MSG_EDIT` 67
`{chatId, messageId, text, elements}` — **всегда весь список**, без разметки — пустой `[]`
(поле не опускается, иначе старая разметка останется).

## Правила

**Чтение (`parse`).**
1. `from` нет — 0. `length` нет — до конца текста. Числа бывают строками (`"8"`).
2. Отрицательные, нулевой длины и начинающиеся за концом текста отрезки выпадают; хвост за
   концом обрезается. Пустой текст — разметки нет.
3. Незнакомые типы (`SPOILER`, `EMOJI`…), элемент без `type` и `LINK` без непустого `url`
   пропускаются. Тип не зависит от регистра. `elements` нет или `null` — разметки нет.
4. Порядок — как у сервера, без слияния: пересекающиеся и вложенные отрезки остаются как есть.

**Запись (`serialize`).**
1. Текст поля обрезается по краям (пробелы и переводы строк); отрезки сдвигаются на срезанное
   начало и обрезаются по новым краям; пустые выпадают.
2. Отрезки одного типа, которые пересекаются или стоят вплотную, сливаются; ссылки — только с
   одинаковым адресом. Разные типы не сливаются.
3. Порядок: по `from`, затем по типу в порядке `STRONG, EMPHASIZED, UNDERLINE, STRIKETHROUGH,
   MONOSPACED, HEADING, QUOTE, LINK, USER_MENTION, ANIMOJI`, затем по длине.
4. Элемент: `{type, from, length}`, у `LINK` ещё `attributes: {url}`.

**Поле ввода (`toggle`, `replace`).**
- Кнопка вида над выделением: выделение целиком размечено этим видом (хоть несколькими
  кусками) — разметка снимается (отрезок режется), иначе всё выделение размечается, сливаясь с
  соседями. Пустое выделение ничего не меняет. Ссылку ставит отдельное действие с адресом
  (`url`), `null` — убрать ссылку; новая ссылка заменяет прежние на выделении.
- Правка текста сдвигает отрезки: вставка до отрезка или в его начало сдвигает, внутри —
  растягивает, в его конце и дальше — не трогает; удалённое вырезается, пустые отрезки выпадают;
  замена внутри отрезка размечается так же.

**Правка сообщения (`edit`).** Разметка исходного сообщения читается по правилам `parse`.
Если обрезанный текст и разметка (по правилам `serialize`) совпали с исходными — запроса нет.
Иначе уходит обрезанный текст и весь список, пустой — `[]`.

## Файлы

Один файл — один вид сценариев, внутри `cases`. `name` совпадает с именем файла.
Отрезки в `spans` — в форме поля ввода: `{type, from, length, url?}`; поле `text` у ожидаемого
отрезка — накрытый им кусок текста (для проверки UTF-16, сравнивать по смещениям).

| `kind` | Вход | `expect` |
|---|---|---|
| `parse` | `text`, `elements` (может отсутствовать или быть `null`) | `spans` |
| `serialize` | `text` (как в поле, можно с пробелами), `spans` | `elements`, иногда `text` (обрезанный) |
| `toggle` | `text`, `spans`, `selection {from, length}`, `type`, `url` (для `LINK`) | `spans` |
| `replace` | `spans`, `edit {at, removed, inserted}` | `spans` |
| `edit` | `original {text, elements}`, `draft {text, spans}` | `request`, `text`, `elements` |

```json
{"kind": "parse", "name": "parse-utf16", "description": "…", "cases": [
  {"name": "emoji-before", "text": "👍 класс",
   "elements": [{"type": "STRONG", "from": 3, "length": 5}],
   "expect": {"spans": [{"type": "STRONG", "from": 3, "length": 5, "text": "класс"}]}}]}
```
