# Имена и номера телефонов: общие сценарии

Какое имя показать у пользователя и как сравнивать номера телефонов с адресной книгой —
одинаково на Swift (`maxly-ios`) и Kotlin (`maxly-shared`, Android). Правило принято и
ядром (max-kmp-core): оно будет и в ядре, и в мосте. Swift проигрывает сценарии в
`NamesFixtureTests` (`maxly-ios/Tests/MaxlyDomainTests`), логика — `PhoneNormalizer`,
`DisplayName` и `AddressBookNames` в `MaxlyDomain`. Новый файл без проигрывателя — ошибка.

Адресная книга читается **только на устройстве** и на сервер не уходит (`SYNC` 21 выключен).

## Номер (`phone-normalize`)

Итог — `+` и цифры с кодом страны (`+79131234567`), `null` — не номер (не сопоставляется).

1. Пробелы (и неразрывные), дефисы и тире, скобки, точки и косая черта убираются.
2. `+` допустим только первым знаком: номер уже с кодом страны, дальше не трогается.
3. Ведущие `00` без `+` — то же, что `+`: `0044 20 7946 0958` → `+442079460958`.
4. Без `+`: 11 цифр с первой `8` — российский номер, `8` меняется на `7`
   (`8 913 123-45-67` → `+79131234567`).
5. Без `+`: ровно 10 цифр — российский номер без кода, спереди `7`
   (`9131234567` → `+79131234567`).
6. Остальное без `+` остаётся как есть (`79131234567` → `+79131234567`).
7. Меньше 7 или больше 15 цифр — не номер: короткие и служебные (`900`) не сопоставляются.
8. Любой другой знак (буква, `+` в середине) — не номер.

Сервер шлёт номер цифрами без `+` (`79131234567`): его приводят так же.

## Адресная книга (`address-book`)

Номера записей приводятся по правилам выше; не-номера пропускаются. Имя обрезается по краям.
Номер, который есть в нескольких записях, получает **первое непустое имя по порядку книги**;
запись с пустым именем имени не даёт.

## Имя (`display-name`)

Приоритет:

1. Адресная книга — если включена («Имена из адресной книги») и номер пользователя совпал.
2. Своё имя контакта: запись `names` с `type: CUSTOM` (контакт переименован).
3. Имя, которое пользователь дал себе: запись `type: ONEME`.
4. Первая запись `names`, у которой есть имя.
5. Номер телефона в виде `+79131234567` (если не приводится — как есть).
6. «Участник».

Адресная книга выше своего имени контакта — поведение по умолчанию (в ядре — настройка
`preferAddressBookNames`, по умолчанию `true`); если порядок поменяют, меняется настройка ядра,
а не клиенты.

Имя записи `names` — `name`, а без него «`firstName` `lastName`» без пустых частей. У записи
`CUSTOM` (контакт переименован) наоборот: «`firstName` `lastName`», а `name` — только если обе
части пустые. Запись без имени пропускается. Номер пользователя сервер шлёт числом
(`79131234567`) — его приводят как строку из цифр. Упоминания (`@`) всегда вставляют имя `ONEME`, не имя из книги.

## Файлы

`kind` — `phone`, `address-book` или `display-name`, внутри `cases`:

```json
{"name": "ru-10-digits", "rule": "…", "raw": "9131234567", "expect": "+79131234567"}
{"name": "duplicate-first-wins", "entries": [{"name": "Иван", "phones": ["+79131234567"]}],
 "expect": {"+79131234567": "Иван"}}
{"name": "book-wins", "addressBookEnabled": true, "addressBook": [{"name": "Мама", "phones": ["8 913 123-45-67"]}],
 "user": {"phone": "79131234567", "names": [{"type": "ONEME", "firstName": "Анна"}]}, "expect": "Мама"}
```
