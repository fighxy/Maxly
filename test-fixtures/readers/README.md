# «Кем прочитано» и строка прочтения: общие сценарии

Список тех, кто прочитал сообщение в группе, и строка «Прочитано»/«Доставлено» в личном
чате реализуются в Orbitle дважды: на Swift (`orbitle-ios`) и на Kotlin (`maxly-shared`,
Android и Desktop). Эти файлы — общие сценарии для обеих реализаций, чтобы они не разошлись.

Swift проигрывает их в `ReadersFixtureTests` (`orbitle-ios/Tests/OrbitleDomainTests`).
Kotlin-проигрыватель пишется отдельно и должен гонять все файлы каталога, как и Swift: новый
файл без проигрывателя — ошибка теста.

## Откуда данные

Отдельного запроса «кто прочитал» в протоколе нет: список собирает клиент.

- **Отметки прочтения** — поле `participants` карточки чата (`LOGIN`, `CHAT_INFO` 48, пуши
  чата): id пользователя → время (мс), до которого он прочитал чат. Поверх него — пуши
  `NOTIF_MARK` 130 `{chatId, userId, mark}`. Из двух отметок одного пользователя побеждает
  бо́льшая.
- **Реакции** — `MSG_GET_DETAILED_REACTIONS` 181 `{chatId, messageId, count: 100}`, ответ
  `reactions: [{userId, reaction}]`. Отреагировавший считается прочитавшим.

`MSG_GET_STAT` 74 сюда не относится: это просмотры и пересылки постов канала.

## Правила

1. **Где доступно.** Только чат `type: "CHAT"` без `videoConversation`, в котором
   участников не больше порога. Участников считает `participantsCount`, а если его нет (`0`) —
   размер `participants`. Порог — `max-readmarks` из серверного конфига, а если
   его нет или он не больше нуля — 100. Не доступно в `DIALOG` (личные, боты, «Избранное» —
   `DIALOG` с id `0`) и `CHANNEL`. Комментарии к постам — тоже нет.
2. **Какое сообщение.** Любое отправленное — своё или чужое. Не доступно для `sending`,
   `failed` и `scheduled`. Возраст сообщения не ограничен.
3. **Прочитал** тот, у кого отметка не раньше времени сообщения: `messageTime <= mark`
   (равное время — прочитано, на 1 мс раньше — нет).
4. **Кого нет в списке.** Себя (`me`) и автора сообщения — ни среди прочитавших, ни среди
   отреагировавших. Веб-клиент Max автора не убирает, а свою реакцию показывает; мы — нет.
5. **Порядок.** Сначала отреагировавшие в порядке ответа 181, с эмодзи. Затем прочитавшие без
   реакции: по убыванию отметки, при равной — по id как числу по возрастанию.
6. **Каждый один раз.** Прочитал и отреагировал — одна строка с эмодзи на месте реакции.
   Повтор пользователя в ответе 181 — берётся первый.
7. **Отметка в строке** (`readMark`, мс) — время последнего прочитанного сообщения, не момент
   чтения. У прочитавшего — его отметка. У отреагировавшего — отметка, если она не раньше
   сообщения, иначе `null`: он в списке только из-за реакции (так решило ядро).
8. Отреагировавший, которого нет в `participants`, всё равно в списке (с `readMark: null`).
9. **Ошибка 181** — список только из прочитавших, ошибки не показываем.
10. **Разбор.** id и отметки бывают числами и строками. Пропускаются: id, который не число;
   отметка, которая не число; реакция без `userId` или с пустой `reaction`.
11. Пустой результат — экран показывает «Пока никто не прочитал».

## Файл `kind: "readers"`

Один файл — один сценарий. `name` совпадает с именем файла, `description` — для человека.
Время — серверное, в мс; id — строки (в `ids-string-and-number` нарочно и числа).

```json
{
  "kind": "readers",
  "name": "reactors-first",
  "description": "…",
  "me": "1",
  "serverMaxReadmarks": 50,
  "chat": {"id": "c1", "type": "CHAT", "videoConversation": false, "participantsCount": 5,
           "participants": {"1": 9000, "2": 6000, "3": 7000, "4": 4000, "5": 5500}},
  "pushedMarks": {"2": 8000},
  "message": {"time": 5000, "author": "1", "state": "sent"},
  "reactions": [{"userId": "4", "reaction": "❤️"}, {"userId": "2", "reaction": "👍"}],
  "expect": {"available": true, "readers": [
    {"userId": "4", "reaction": "❤️", "readMark": null},
    {"userId": "2", "reaction": "👍", "readMark": 6000},
    {"userId": "3", "reaction": null, "readMark": 7000},
    {"userId": "5", "reaction": null, "readMark": 5500}]},
  "steps": [
    {"push": {"userId": "3", "mark": 5000}, "expect": {"available": true, "readers": […]}}
  ]
}
```

- `serverMaxReadmarks` — необязательное: нет поля — сервер порог не прислал (100).
- `chat.participants` — как в карточке чата; `pushedMarks` — пуши 130, уже пришедшие к
  моменту открытия (может быть `{}`).
- `message.state` — `sent`, `sending`, `failed` или `scheduled`.
- `reactions` — ответ 181. Вместо него может стоять `"reactionsError": true` — запрос не
  удался.
- `expect.available` — показывать ли пункт и раздел; при `false` `readers` всегда `[]`.
- `expect.readers` — список по порядку; `reaction: null` — прочитал без реакции; `readMark` —
  отметка (правило 7), `null` — в списке только из-за реакции.
- `steps` — необязательные: каждый шаг — пуш 130 при открытом списке (отметка сливается с
  прежними, бо́льшая побеждает) и ожидаемый после него список. Шаги идут по порядку и
  накапливаются.

## Файл `kind: "info"`

Строка прочтения на экране сведений о сообщении в личном чате. Только своё отправленное
(`sent`) сообщение в `DIALOG`, кроме «Избранного» (id `0`): «Прочитано», если отметка
собеседника больше нуля и не раньше времени сообщения, иначе «Доставлено». В остальных
случаях строки нет (в группе вместо неё раздел «Кем прочитано»).

```json
{
  "kind": "info",
  "name": "info-private-status",
  "cases": [
    {"name": "read-equal", "chat": {"id": "c1", "type": "DIALOG"}, "own": true, "state": "sent",
     "messageTime": 5000, "peerMark": 5000, "expect": {"status": "read", "text": "Прочитано"}}
  ]
}
```

`expect.status` — `read`, `delivered` или `null` (строки нет), `text` — сама строка или `null`.
Строка только для своих сообщений: у входящих её нет никогда.

## Файл `kind: "edited"`

Строка «изменено» на экране сведений. Источник — `updateTime` сообщения (мс): `null`, `0` или
нет поля — сообщение не изменялось (мост iOS отдаёт `0`, ядро — `null`). Значение — число или
строка с числом.

```json
{
  "kind": "edited",
  "name": "info-edited",
  "cases": [
    {"name": "never-null", "updateTime": null, "expect": {"edited": false, "time": null}},
    {"name": "edited", "updateTime": 8000, "expect": {"edited": true, "time": 8000}}
  ]
}
```

## Сценарии

| Файл | Что проверяет |
|---|---|
| `reactors-first` | сначала реакции в порядке сервера, затем прочитавшие по отметке |
| `read-and-reacted-once` | прочитал и отреагировал — одна строка; повтор в 181 не дублирует |
| `mark-equals-time` | равное время — прочитано, на 1 мс раньше — нет |
| `exclude-self` | себя нет ни в прочитавших, ни в реакциях |
| `exclude-author` | автора чужого сообщения нет, даже с реакцией |
| `own-message`, `incoming-message` | доступно и для своего, и для чужого |
| `not-private`, `not-saved-messages`, `not-channel`, `not-video-conversation` | где списка нет |
| `message-sending`, `message-failed`, `message-scheduled` | для неотправленного списка нет |
| `group-size-100`, `group-size-101` | порог по умолчанию — 100 включительно |
| `group-size-server-lower`, `group-size-server-higher` | порог из серверного конфига |
| `group-size-count-missing` | нет `participantsCount` — считаем по `participants` |
| `pushed-mark-newer`, `pushed-mark-older` | пуш 130 и карточка: побеждает бо́льшая отметка |
| `live-push` | открытый список обновляется пушами |
| `reactor-not-participant` | отреагировавший вне `participants` в списке |
| `reactions-error` | ошибка 181 — только прочитавшие |
| `nobody` | пустой список |
| `readers-order-ties` | равные отметки — по id как числу |
| `ids-string-and-number` | числа и строки, мусорные записи |
| `info-private-status` | «Прочитано» / «Доставлено» в личном чате, только своё |
| `info-edited` | «изменено»: `updateTime` `null`/`0` — не изменялось |
