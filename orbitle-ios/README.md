# orbitle-ios

iOS-клиент Orbitle на SwiftUI. Слои описаны в [`docs/architecture.md`](../docs/architecture.md). Komet — карта функций клиента Max ([`docs/komet-reference.md`](../docs/komet-reference.md)), не образец структуры. Вкладка «Настройки» описана в [`docs/settings.md`](docs/settings.md). Реакции на сообщения — в [`docs/reactions.md`](docs/reactions.md). Вложения (фото, видео, файлы, контакты) — в [`docs/attachments.md`](docs/attachments.md). Приватный режим — в [`docs/privacy-mode.md`](docs/privacy-mode.md). Анимации и правила плавности — в [`docs/animations.md`](docs/animations.md). Кэш медиа и экран «Данные и память» — в [`docs/storage.md`](docs/storage.md). Сохранение в «Фото» и «Файлы» — в [`docs/saving.md`](docs/saving.md). Расшифровка голосовых — в [`docs/transcription.md`](docs/transcription.md). Шапка чата и профиль — в [`docs/profile.md`](docs/profile.md). Эмодзи и стикеры — в [`docs/stickers.md`](docs/stickers.md). Звонки (ws2, WebRTC, CallKit) — в [`docs/calls.md`](docs/calls.md).

## Слои

- `Sources/OrbitleDomain` — модели, протоколы репозиториев, ошибки, разбор ссылок `orbitle://`. Чистый Swift.
- `Sources/OrbitleData` — SwiftData, URLSession, очередь исходящих, синхронизация и сессия. Ядро сюда входит только как протокол `MaxCore`.
- `Sources/OrbitlePresentation` — логика экранов без SwiftUI: `AuthViewModel`, `PhoneNumber`, `ChatListViewModel`, `ChatListFormatter`, `ChatViewModel`. Зависит только от `OrbitleDomain`, покрыта тестами `Tests/OrbitlePresentationTests` на фейковых репозиториях.
- `Sources/OrbitleUI` — цвета, отступы, аватар, строка чата (принимает готовые строки), пузырь сообщения.
- `Sources/OrbitleCallMedia` — WebRTC (Google WebRTC M154, сборка stasel): соединение, микрофон, камера, показ экрана, аудиосессия и вид видео. Логика звонка в `OrbitleData/Calls` с ним не связана и тестируется на фейках.
- `OrbitleApp` — точка входа, контейнер, навигация и тонкие SwiftUI-экраны. Это таргет Xcode. `import MaxIos` живёт только в `OrbitleApp/Core/MaxIosCore.swift`.

Профиль устройства остаётся внутри ядра: Android, Pixel 8. Приложение не подставляет данные iPhone.

## Что есть в этом прототипе

Вход по SMS, пароль 2FA, регистрация, восстановление сессии из токена ядра (Keychain `com.max.kmp.default`). Пока сокет поднимается, показывается локальный кэш. Отклонённый токен открывает вход и не стирает базу. Явный выход и вход другим пользователем стирают базу и дисковый кэш медиа.

### Вход

- Номер: маска `+7 999 123-45-67`, стирание через разделитель удаляет цифру, `8…` и `7…` приводятся к `+7…`. Российский номер должен начинаться с 3, 4, 7, 8 или 9, международный — 8–15 цифр.
- Код: только цифры, не длиннее ожидаемого, полный код отправляется сам. Повторная отправка доступна через 30 секунд, отсчёт виден на кнопке. Если сервер сообщил, что код устарел, новый код запрашивается автоматически, поле очищается, отсчёт начинается заново.
- Пароль 2FA с подсказкой, регистрация: имя обязательно (до 60 символов), фамилия нет, пробелы по краям обрезаются.
- «Назад» отменяет текущий запрос и забывает попытку: поздний ответ ядра шаг уже не меняет. Отмена не показывается как ошибка, после неверного кода или пароля поле очищается. Тексты ошибок зависят от шага (неверный код, неверный пароль, лимит попыток).

### Список чатов

- Состояния: загрузка, список, пусто, нет сети, ошибка с кнопкой «Повторить». Плашка «Подключение…» или «Нет соединения» над сохранённым списком. Когда связь возвращается после обрыва, список сразу догружается, плашка в это время говорит «Обновление…». Перестановка строк анимируется.
- Сортировка по времени последнего события, при равенстве по id. Время строки: `HH:mm` сегодня, «вчера», день недели в пределах недели, «5 мар» в этом году, `dd.MM.yyyy` раньше — не зависит от локали устройства. Бейдж до «99+», для VoiceOver фраза с числом непрочитанных.
- Открытый чат отмечается прочитанным сразу и снова, если в него пришло сообщение, пока он на экране. Если непрочитанных нет, отметка на сервер не уходит.

### Синхронизация

Правила записи пушей описаны в [`Sources/OrbitleData/Storage/README.md`](Sources/OrbitleData/Storage/README.md#правила-слияния). Поведение сверено с клиентом Komet (код не заимствован).

### Прочее

Список чатов, история страницами по 50, отправка текста через исходящую очередь, пуши ядра (сообщение, правка, удаление, чат, прочтение). Открытый чат отмечается прочитанным. Чат с непрочитанными открывается на разделителе «Непрочитанные сообщения» над первым из них, он уходит после своего ответа. Превью ссылок (`SHARE`) — карточка в пузыре. Inline-кнопки ботов под пузырём: нажатие уходит боту (118), текст ответа показывается уведомлением, адрес открывается; кнопки-ссылки открываются, «копировать» кладёт текст в буфер, `OPEN_APP` и капсула «Открыть приложение» у бота с мини-приложением открывают лист мини-приложения. Медиа качаются через URLSession в каталог с лимитом 200 МиБ. Отмена задачи (ушли с экрана) отменяет и загрузку, отмена не показывается как «нет сети».

Ошибка авторизации ядра (`AUTH`) означает «неверный пароль» только на шаге пароля; в остальных запросах она показывается как общая ошибка ответа. Выход, нажатый во время входа, побеждает: поздний ответ входа сессию не открывает.

Шапка списка чатов как в Telegram — первые строки самого списка: истории, поиск капсулой, папки стеклянной капсулой с «таблеткой» выбранной. Поиск уезжает вместе со списком, папки, дойдя до панели навигации, закрепляются (их копия сверху на размытии, которое к низу тает без линии). Остановка посреди историй или поиска доводится до края. Истории (схема Komet `feature/FullStack`): спрятаны над поиском, у заголовка «Чаты» — стопка их аватаров; открываются потягиванием списка вниз или касанием стопки, инерция сверху останавливается на поиске (`ChatListHeaderGeometry`, смещение и палец — прямо из `UIScrollView` списка); раскрытая полоса — «Ваша история» с кнопкой новой, затем кольца — сначала непросмотренные, потом свежие; новая история — ещё и кнопкой справа в панели навигации; кольца на аватарах личных чатов (собеседник — `id диалога ^ свой id`), в шапке чата и в профиле. Просмотр на весь экран: полосы прогресса, фото 5 секунд, видео по длине, касание слева — назад, справа — вперёд, удержание — пауза, свайп вниз — закрыть, вбок — к соседнему владельцу; продолжение с первой непросмотренной, удаление своей. Публикация фото или видео из медиатеки на сутки: всем или только контактам.

Звонки: аудио и видео один на один, групповые по ссылке, входящие с CallKit, смена камеры, показ экрана приложения, плашка идущего звонка и удаление из журнала на сервере ([`docs/calls.md`](docs/calls.md)). Пуши APNs (и входящие звонки, пока приложение выгружено) и QR-вход нового устройства в этот прототип не входят.

## Сборка

Ревизия ядра записана в `core.lock`. На macOS с JDK 17 и Xcode:

```bash
bash scripts/fetch-core.sh
```

Скрипт кладёт статический `Vendor/MaxIos.xcframework` (каталог в `.gitignore`) и не линкует `MaxShared` отдельно: он уже внутри `MaxIos`. Дальше открывается `Orbitle.xcodeproj`, схема `Orbitle`.

Ядро из локальной папки вместо GitHub (ревизия `core.lock` тогда не проверяется):

```bash
MAX_KMP_CORE_DIR=~/src/max-kmp-core bash scripts/fetch-core.sh
```

### Установка на iPhone

```bash
bash scripts/build-ipa.sh            # или MAX_KMP_CORE_DIR=… / SKIP_CORE=1
```

Скрипт собирает Release для устройства без подписи и кладёт `build/Orbitle.ipa`. Его подписывают своим сертификатом (Sideloadly, AltStore, eSign и т. п.) и ставят на телефон. CI делает то же и выкладывает `.ipa` в артефакты прогона.

Тесты библиотек (`OrbitleDomainTests`, `OrbitleDataTests`, `OrbitlePresentationTests`) ядро не требуют:

```bash
swift test --package-path orbitle-ios
```

Они собираются и для macOS 14, чтобы прогон шёл на CI. Само приложение остаётся iOS 17.

На Windows `scripts/fetch-core.ps1` только забирает исходники ядра на ту же ревизию. XCFramework там не собирается.

## CI

Workflow `.github/workflows/ios.yml` на `macos-15` выбирает Xcode 26.3 (SDK iOS 26.2, Swift 6.2) и гоняет `swift test` и сборку приложения: только с SDK iOS 26 в приложение попадает код под `#available(iOS 26)` (стекло Liquid Glass, системный указатель списка). Минимальная версия iOS прежняя, 17.0. `MaxIos.xcframework` собирается Xcode 16.2 (`DEVELOPER_DIR`): Kotlin/Native 2.1.10 в ядре не разбирает заголовки SDK 26. Проверка запуска идёт в симуляторе iOS 26.2 (`ORBITLE_SIM_RUNTIME`), а сборка .ipa проверяет, что в бинарнике есть вызовы `glassEffect`. `swift test` вшивает `Tests/OrbitleDataTests/Info.plist` в тестовый бинарник: SwiftData требует `CFBundleName`. Приложение (`OrbitleApp`, `MaxIosCore.swift`) компилируется только в этой сборке, `swift test` его не видит. Сборка приложения клонирует приватный `fighxy/max-kmp-core`, поэтому в секретах репозитория Orbitle нужен `MAX_KMP_CORE_TOKEN`: PAT с правом чтения `fighxy/max-kmp-core`. Без секрета сборка приложения пропускается с предупреждением, а тесты библиотек идут как обычно. `GITHUB_TOKEN` самого Orbitle к ядру доступа не имеет.
