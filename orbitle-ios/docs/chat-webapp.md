# Кнопка «Открыть» в списке чатов

У диалога с ботом, у которого есть мини-приложение, справа в строке списка стоит капсула
«Открыть». Она запускает мини-приложение бота, не открывая чат. Касание по остальной строке
по-прежнему открывает чат.

## 1. Откуда флаг

Ядро `1364e91` отдаёт `IosChat.hasWebApp`. Оно `true` только у личного чата с ботом, чьи опции
ядро уже загрузило и среди них есть `BOT` и `HAS_WEBAPP` / `HAS_WEB_APP` / `WEBAPP`. У групп,
каналов, людей и бота с ещё не загруженным профилем — `false`. Ядро пересчитывает флаг, когда
меняются чаты или пользователи.

Мост (`MaxIosCore.chat`) кладёт флаг в `CoreChat.hasWebApp`, запись списка (`ChatRecord`)
сохраняет его в базе (`SDChat.hasWebApp`), строка списка читает его в `Chat.hasWebApp`.
Ответ ядра — правда всегда: `false` снимает прежнее `true`. Если бот не прислал флаг
(`nil`), в базе остаётся то, что было. `true` заодно помечает чат ботом (`isBot`).

## 2. Строка

`ChatListFormatter` ставит `ChatListItem.hasWebApp` только у личного чата, не «Избранного».
`ChatRow` рисует капсулу справа, перед бейджем непрочитанных, если передан запуск
(`onOpenApp`). Кнопка `borderless`, поэтому её касание не выбирает строку списка и чат не
открывается. VoiceOver видит отдельное действие «Открыть приложение».

В приватном режиме с заглушками кнопки нет: заглушка строится без флага.

## 3. Запуск

`ChatListViewModel.botApp(for:)` считает бота как `id чата ^ свой id` и отдаёт
`BotAppRequest(botId:, chatId:, startParam: nil, title: название чата)`. `ChatListView`
открывает его в `MiniAppSheet` через `AppContainer.botAppModel` → `launchBotApp` — тем же
путём, что кнопка «Открыть приложение» внутри чата с ботом.

## 4. Тесты

- `ChatListFormatterTests.webApp`: флаг у бота, нет у группы, обычного чата и «Избранного».
- `ChatListBotAppTests`: бот считается по id чата и своему id; без флага и без своего id
  запроса нет.
