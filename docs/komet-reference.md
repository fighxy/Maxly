# Памятка: архитектура клиента Komet

Источник: [KometTeam/Komet](https://github.com/KometTeam/Komet). Разбор сделан по структуре репозитория на 29.09.2026.

**Актуальная ветка — `feature/FullStack`**, а не `main`: схемы запросов и поведение сверяются с ней. С 05.10.2026 по ней перепроверены: inline-кнопки (118, `OPEN_APP` с `chat_id` из ссылки `webApp`), запуск мини-приложения (160), опции мини-приложения бота, комментарии канала (только при `options.COMMENTS == true`), жалобы (161/162, типы 2 и 6), блокировка (34 `BLOCK`/`UNBLOCK`, состояние по чёрному списку), общие чаты (198), вступление (57 `{link}`) и выход (58 `{chatId}`).

## 1. Что это

Komet это клиент мессенджера Max на Dart и Flutter. Интерфейс один для всех платформ: Android, iOS, macOS, Windows и Linux. Протокол, сеть, база и UI живут в одном Dart-пакете `lib/` (около 430 файлов). На Rust вынесена только криптография, она подключается через `flutter_rust_bridge` (`native/komet_crypto/`).

## 2. Ключевые каталоги

```
lib/
  backend/        api.dart и modules/ с предметными модулями:
                  chats, messages, outbox, contacts, calls, stickers,
                  stories, polls, file_uploader, upload_service…
  core/
    transport/    TLS-сокет, диспетчер пакетов, мониторинг трафика
    protocol/     формат пакета, таблица опкодов
    storage/      app_database (sqflite), token_storage, черновики, *_store
    cache/        кэши сообщений и информации о чатах
    media/        opus/ogg, оптимизация картинок, воспроизведение, видеокружки
    calls/        звонки на WebRTC, сигналинг, SFU
    push/         пуши (Firebase), мост уведомлений
    crypto/       шифрование чатов
    links/        диплинки и ссылки Max
    config/       настройки внешнего вида и поведения
    utils/        логгер, загрузки, медиакэш, проверка обновлений
  frontend/       screens/, widgets/, commands/ (slash-команды), debug/
  models/
  l10n/
native/komet_crypto/   Rust-криптография
android/ ios/ macos/ linux/ windows/   платформенные обёртки Flutter
```

## 3. Слои

- **core** отвечает за транспорт, протокол, хранилища и медиа.
- **backend** содержит предметные модули поверх API: чаты, сообщения, контакты, звонки и другие.
- **frontend** содержит экраны и виджеты.

Разделение сделано только каталогами внутри одного пакета, формальных модульных границ нет.

## 4. Что полезно для Maxly

- Набор модулей `backend/modules` можно использовать как карту функций Max, которые клиент должен поддерживать.
- Исходящие сообщения идут через отдельный `outbox`, это подтверждает нашу схему с очередью исходящих.
- Кэши сообщений и информации о чатах (`core/cache`) показывают, какие данные стоит держать под рукой ради скорости.
- Медиа-модуль с оптимизацией картинок перед отправкой, кодированием голосовых в opus/ogg и отдельным медиакэшем.

## 5. Чем слабее нашей архитектуры

- Нет слоя репозиториев и внедрения зависимостей. Экраны обращаются к модулям-синглтонам напрямую.
- Тестов почти нет.
- Общий код включает UI. В KMP общее только ядро, а интерфейс нативный на каждой платформе. Из-за этого iOS-вид в Komet приходится подстраивать внутри Flutter-интерфейса.

## 6. Вывод

Komet стоит использовать как шпаргалку «что должно быть в клиенте Max», но не как образец структуры.

Сверка функций Komet с тремя клиентами Maxly и план работ — в [komet-gap-map.md](komet-gap-map.md).
